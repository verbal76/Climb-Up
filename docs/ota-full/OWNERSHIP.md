## Interface contracts (change only by request)
E1 relies on this `hostkit` surface owned by E2 and E2 keeps it source-compatible (new methods are fine; changing or removing one needs a REQUEST to E1 first):
`ModuleStore(File root, TrustedKeys, HostInfo)`, `.withSaveGuard(SaveGuard)`, `.boot() : ModuleStore.Boot{dir, manifest, note, overrides, recovery()}`, `.loadFailed(String) : Boot`, `.confirm()`, `.setClimbInProgress(boolean)`, `.installBaseline(File) : String|null`, `.openStaging() : File`, `.commitStaging() : String|null`, `.preflight(byte[], byte[]) : String|null`, `.stagedVersion()`, `.assets() : AssetStore`, public `State st` fields read by diagnostics; `ModuleDownloader(store, Fetcher, baseUrl).check() : String`; `OverlayFiles(Files, Map<String,AssetManifest.Asset>, AssetStore, Consumer<String>)`; `TrustedKeys.add/revoke/trusts`; `DirSnapshots(File, File, Set<String>)`.
E2 relies on this surface owned by E1: `GameModule`/`HostEnv` in `modspi`, `HostBoot.start/failed(...)` and `HostBoot.Started`, `LabLauncher`/`LabCommon` behaviour (`prop.*` extras, `selftest`, `updateBase`), `lib.sh` helpers, `build_climb_fixtures.sh` outputs (baseline + `c2..c5`), the `climbhost` APK and its `files/host/**` on-device layout.
Both sides keep the cross-surface tests green: `ModuleStoreTest`/`DownloaderTest`/`AssetDeliveryTest`/`SaveGuardTest` (E2) and `ClimbModuleTest` + the device scenarios (E1).

## Requests (no cross-editing)
A change needed in a file you do not own is a **REQUEST**, sent with `send_message` to the other session, one message per request, in this shape: `REQUEST <id> from E?: <file>: <exact narrow change or interface needed>: <why/test that needs it>`. The owner implements it in its own branch (or declines with a reason), then replies `DONE <id> <sha>` (or `DECLINED <id> <reason>`). New files in your own paths never need a request. Do not wait idle: continue with other work.

## Integration
E2 pushes only `exp/ota-reliability` (workflows: `otalab.yml`, `otalab-assets.yml`, `otalab-reliability*.yml`; all non-publishing, `contents: read`, no secrets). E1 merges `origin/exp/ota-reliability` into `exp/ota-full` at milestones with an ordinary merge commit (disjoint ownership, so no conflicts by construction), runs the full integrated validation, and fixes only E1-owned fallout; E2-owned defects go back to E2 as a REQUEST with the failing log. E1 merges `exp/ota-full` into E2's view only by E2 pulling it (`git merge origin/exp/ota-full`) when it needs new E1 work. Nobody rebases, force-pushes or rewrites the other's history.
