# Upwardly 16-KPI reporting suite: read-only audit (branch fix/build-83-root-causes @ 72c0a6d)

Abbreviations: CP = tools/ci/cert_package.py, LR = core/src/test/.../sim/LaneReport.java, WF = .github/workflows/difficulty-report.yml, CPD = docs/CERTIFICATION_PACKAGE.md, FW = docs/KPI_FRAMEWORK.md, B83 = docs/verification/build83/BUILD83_VALIDATION_REPORT.md.
Status engine: `KPI.finish` (CP:600-608). Any failing check gives FAIL. Only KPIs flagged fully objective (1, 2, 14, 15; CP:73-92) can PASS automatically. Every other KPI is NOT VERIFIED until an analyst override sets it (`apply_overrides`, CP:1139-1169). The analyst PASS is refused when the KPI has missing inputs or an automatic FAIL.
**Real-course evidence, for every row:** CP has never run on a real campaign. It was tested only on an old rules-12 sample campaign (CPD:115) and on synthetic fixtures (`selftest`, CP:2000-2028). The Build 83 progress report says "The certification campaign has not run" (docs/BUILD83_PROGRESS_REPORT_2026-10-30.md:55). B83 is a hand-written analyst evaluation built from lane_report/batch_summary outputs of run 40884899102 @ c8ef538 (rules 18). Its charts (01_difficulty_curves…08_performance) and kpi_scorecard.csv (47 rows in 8 legacy categories, not the KPI ids) are not CP outputs. The "real" column quotes B83's manual verdict.

## (b) Reporting and tooling gaps (separate from gameplay)
1. **Never exercised on real courses.** No CP output exists for any real campaign. B83's KPI table was produced by hand outside CP. The CP selftest covers only the empty, legacy and CI-evidence cases (CP:2004-2028), not the 7B, 11 or 12 logic. There is no unit-test file for CP (tools/ci has only test_publish_release.sh).
2. **Workflow defaults are not the standard sample.** WF:10 defaults seeds to ["1","2"]. The certify run must pass three seeds explicitly, or KPIs 1 and 2 can only be NOT VERIFIED (sample_check, CP:1085).
3. **The documented overrides path does not exist.** CPD:15 and WF:24 cite docs/verification/build83/evaluation_overrides.json, but the file is absent. CP then exits with an error (CP:2108).
4. **Hardcoded build label.** WF:183 calls cert_scorecard.py on `certification/Upwardly_Build83_Certification`. Passing a different `--build-label` in cert_args breaks the step, and the default label is "Build 83" (CP:2100).
5. **Evidence is self-attested.** The fingerprint, CI and release inputs are typed `k=v` strings with no lookup through the GitHub API. Because CP:1090-1097 accepts that evidence, KPIs 1, 14 and 15 can PASS on it alone.
6. **KPI 14 and 15 PASS too easily.** Their framework sub-items (replays, saves, gamepad, Steam) are non-required, so they never block an automatic PASS.
7. **An analyst can soften an automatic FAIL.** Setting WATCH or NOT VERIFIED over an automatic FAIL is accepted and only listed in the exceptions (CP:1159-1161).
8. **No baseline comparison.** Question 4 ("better than the previous build", FW:66) is free text from the overrides (CP:1858). CP computes no Build 82 deltas (compare_runs.py and kpi_data.json are separate tools).
9. **LR outputs CP never reads:** ledger.csv, forks.csv (route length), platforms.csv, fork_attempts.csv, windows_v2_reference.csv, counts.csv (loaded, unused), and the hazards.csv timing and exposure columns.
10. **Route integrity and shortcut detection are absent from the campaign path.** T5Probe `audit` (T5Probe.java:149) runs only in the WF `probe` job (WF:87-113). That job cannot run in the same dispatch as consolidate or certify (WF:116). Its output (route_skipped, search_reached) reaches no KPI.
11. **The geometry audit is outside CP.** geometry_audit.py runs only when courses carry geometry_samples.csv, which requires `-Dclimb.geomAudit=true` in jvm_props (WF:156-162, LR:249). Its pitch, clearance, reach_gap and dead_zone tables would inform KPI 2 (geometry integrity), KPI 3 (spacing, jump distance) and KPI 16. Without them, KPI 2's "geometry integrity" means only "no integrity.csv rows".
12. **No dedicated charts** for KPIs 1, 2, 7A, 14 and 15. KPI 3 has only lane curves.
13. **Outputs exist in code:** PNG + SVG charts (make_charts CP:1699-1724, 19 figures); data/*.csv + package_data.json (CP:1214-1242); kpi_measurements.json/.csv (:1245); offline dashboard (template cert_dashboard.html, data inlined; selftest checks for external references, :2063-2079); executive and technical PDFs plus TECHNICAL_REPORT.md (:1843-1891, :2135); inner manifest with SHA-256 of every input and output (:1934-1981); ZIP, outer manifest and .sha256 (:1984-1996).
14. **Dependencies are covered.** The runtime needs only Python 3 and matplotlib: PDFs use matplotlib PdfPages (CP:31), there is no reportlab, and numpy comes in with matplotlib. WF:179 installs matplotlib before running CP. Java is optional and used only to record the version in the manifest.

## (c) Verdict
**Not ready to run on a frozen candidate.**
- **Mechanically**, the packager would run in CI: its dependencies are installed, every output is implemented and the selftest is wired.
- **There is no candidate to run it on yet.** Since c8ef538, CourseGenerator has 20 commits and tuning.json changed. Rules version 18 and the pinned fingerprint (DeterminismTest.java:108) are unchanged, and the progress report waits for the Rules 19 freeze. So KPI 1 identity is not trustworthy until the rules version and fingerprint are bumped and frozen.
- **The tool is unproven on real courses:**
  - it has never run on a real campaign (the only test data is rules 12);
  - the documented overrides file is missing;
  - the default seeds give an undersized sample.
- **What a run can and cannot decide.** Even run correctly, CP can only:
  - decide KPIs 2 and 10, plus the rule-based FAIL checks in 7B, 11 and 12;
  - pass KPIs 1, 14 and 15 on self-attested evidence.

  KPIs 3-9, 13 and 16 always need an analyst, with no numeric targets. Shortcut and route integrity (T5) and the geometry audit stay outside the package.
- **Minimum before a certification dispatch:**
  1. Freeze the rules version and fingerprint.
  2. Dispatch with seeds of three per mode.
  3. Commit a real evaluation_overrides.json, or drop the `--overrides` argument.
  4. Supply fingerprint and CI evidence from the full CI run on the same SHA.
  5. Decide whether the T5 audit and the geometry audit outputs must feed KPI 2 and KPI 10.
